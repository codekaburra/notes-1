Uniswap v3 與 v4

2026-09-09 · DeFi / AMM

v3 與 v4 是整個 Uniswap 家族中概念跳躍最大的兩代，因為兩者各自解決的是完全不同層面的問題。以下分別說明，最後以一句話區分。

v3 —— 集中流動性

v2 到 v3 只有一個核心思想，其餘皆為其衍生結果。

v2：流動性平均攤在 0 → ∞ 的整條價格曲線上（x·y=k）。然而交易僅發生在現價附近，因此大部分資金停留在永遠不會成交的價位，形同閒置。

v3：流動性提供者（LP）自行選定一段價格區間 [Pa, Pb]，將資金集中投入。在區間之內，其部位等同於一個深度極高的 v2 池；一旦價格離開此區間，部位即轉為單一資產，且不再賺取任何手續費。

此一改動連帶產生四個結果：

  • Tick（刻度）：價格空間被切分為離散的 tick，price = 1.0001^tick，每個 tick 相差 0.01%。流動性掛在相鄰兩個 tick 之間；價格每跨越一個 tick，便有一批流動性被啟用或退出。
  • 部位成為 NFT：v2 的 LP 代幣可互換（ERC-20），因所有部位相同；v3 每個部位的區間不同，因此改以 ERC-721 表示，各自獨立。
  • 多個費率層：0.01% / 0.05% / 0.30% / 1.00%，每個費率為獨立的池。同一交易對可能同時存在數個 v3 池。
  • 由被動轉為主動：集中意味著資本效率提升，但價格離開區間即停止收益，且無常損失被放大。v3 的 LP 需持續監控並調整區間，因此專業造市者取得了多數的 v3 流動性。

將區間設定得極窄（近乎一個價位），v3 的 LP 部位即近似一張限價單——此為 v2 無法達成之功能。

v4 —— Hooks 與架構重寫

v4 的定價數學（集中流動性、tick）大致直接繼承自 v3。v4 改變的並非「如何定價」，而是三件事：如何部署、代幣如何流動、能否注入自訂邏輯。

改動v3v4
Hooks無，邏輯寫死每個池可掛載一個 hook 合約，於 beforeSwap、afterSwap、beforeAddLiquidity 等生命週期節點執行自訂程式碼
Singleton每個池為一個獨立部署的合約所有池共用單一 PoolManager 合約
Flash accounting每一步皆實際轉入、轉出代幣一筆交易內僅記帳（採 EIP-1153 暫時性儲存），最終只結算淨額
原生 ETH須先包裝為 WETH直接使用 ETH

Hooks 為 v4 的核心。hook 是一個合約，於建池時指定。此後該池每次交易，PoolManager 會在成交前後回呼此 hook。因此動態費率、鏈上限價單、TWAMM、自訂曲線、MEV 內化等機制，過去需另建一整條 DEX，如今僅需數百行的 hook 即可實現，無須分叉 Uniswap。

Singleton 使建立新池從「部署合約」變為「一次狀態更新」，gas 成本大幅下降，且多跳交易無須在合約之間搬移代幣。Flash accounting 則讓複雜路由的多跳交易顯著更便宜。

一句話區分

v3 解決「資本效率」——將流動性集中於現價附近，代價是 LP 需主動管理。v4 保留 v3 的定價機制不變，再疊加「可程式化（hooks）」與「更省 gas 的架構（singleton 與 flash accounting）」。

若以比喻表示：v3 將 AMM 由「灑水器」改為「精準噴頭」；v4 則將整套機器變為「可安裝外掛的作業系統」。

Uniswap v3 & v4

2026-09-09 · DeFi / AMM

v3 and v4 are the two biggest conceptual leaps in the Uniswap family, because each solves a problem at a completely different layer. Here is each in turn, with a one-line distinction at the end.

v3 — Concentrated liquidity

There is a single core idea from v2 to v3; everything else follows from it.

v2: liquidity is spread evenly across the entire price curve, 0 → ∞ (x·y=k). But trading only happens near the current price, so most capital sits at prices that never trade — effectively idle.

v3: a liquidity provider (LP) chooses a price range [Pa, Pb] and concentrates capital within it. Inside the range the position behaves like a very deep v2 pool; once price leaves the range, the position becomes a single asset and earns no fees.

Four consequences follow:

  • Ticks: price space is discretised into ticks, price = 1.0001^tick, each tick 0.01% apart. Liquidity sits between two adjacent ticks; each time price crosses a tick, a batch of liquidity is activated or retired.
  • Positions become NFTs: v2 LP tokens are fungible (ERC-20) because all positions are identical; each v3 position has a different range, so they are ERC-721, each unique.
  • Multiple fee tiers: 0.01% / 0.05% / 0.30% / 1.00%, each a separate pool. One pair may have several v3 pools at once.
  • Passive becomes active: concentration raises capital efficiency, but earnings stop once price leaves the range, and impermanent loss is amplified. v3 LPs must monitor and re-adjust, which is why professional market makers hold most v3 liquidity.

Set the range extremely narrow (nearly a single price) and a v3 position approximates a limit order — something v2 cannot do.

v4 — Hooks and an architectural rewrite

v4's pricing maths (concentrated liquidity, ticks) is largely inherited directly from v3. What v4 changes is not how it prices, but three things: how it deploys, how tokens move, and whether custom logic can be injected.

Changev3v4
Hooksnone; logic is fixedeach pool can attach a hook contract that runs custom code at lifecycle points: beforeSwap, afterSwap, beforeAddLiquidity, etc.
Singletoneach pool is a separately deployed contractall pools share one PoolManager contract
Flash accountingtokens actually transferred in/out at every steponly bookkeeping within a transaction (via EIP-1153 transient storage); only the net is settled at the end
Native ETHmust wrap to WETHuses ETH directly

Hooks are the heart of v4. A hook is a contract specified at pool creation. Thereafter, on every swap, the PoolManager calls back into the hook before and after execution. Dynamic fees, on-chain limit orders, TWAMM, custom curves, MEV internalisation — mechanisms that once required building an entire new DEX — now take a few hundred lines of hook, without forking Uniswap.

Singleton turns creating a pool from "deploying a contract" into "one state update," cutting gas sharply and letting multi-hop swaps avoid moving tokens between contracts. Flash accounting makes complex multi-hop routes markedly cheaper.

One-line distinction

v3 solves capital efficiency — concentrating liquidity near the current price, at the cost of active LP management. v4 keeps v3's pricing unchanged and layers on programmability (hooks) and a cheaper architecture (singleton and flash accounting).

By analogy: v3 turned the AMM from a sprinkler into a precision nozzle; v4 turns the whole machine into an operating system you can install plugins on.
