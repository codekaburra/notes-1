DeFi 整合：從使用者意圖到確認與復原

2026-10-08 · FOUNDATIONS · DEVELOPMENT · PRODUCT · RISK

本篇導覽
  1. 先固定整合邊界
  2. 步驟一至四：讀取與簽署前檢查
  3. 步驟五至八：授權、送出、確認
  4. 失敗矩陣：不要因 timeout 就重送
  5. 驗收與上線
  6. 參考來源

以「USDC 換 ETH」為主線。完整整合不只是一行 writeContract：需要確認身份與單位、讓使用者理解授權、執行受約束的操作，再證明結果與處理失敗。

三句話版本
  • 完整整合不是一行 writeContract，而是八個步驟：前四步只讀取與模擬、不花錢，從第五步開始才產生鏈上交易與成本。
  • timeout 不代表失敗。交易可能仍在 pending，也可能已經執行；盲目重送可能讓同一件事發生兩次。
  • 「完成」要由receipt、正確的 event 與實際的餘額變化共同證明，並等到產品需要的 finality。

誰讀哪裡：前端／後端工程師 → 八步驟圖、程式碼與失敗狀態機；PM → 失敗矩陣與「驗收與上線」，決定什麼算完成、誰負責善後。

先固定整合邊界

建立 deployment manifest：chain ID、RPC、token address/decimals、Router/Factory/Permit2、ABI、code hash、SDK 與 compiler 版本、fork block、官方來源。用 npm --save-exact 安裝已選版、提交 lockfile，CI 用 npm ci；不要把 latest、任意 explorer ABI 或同 symbol token 當成可重現版本。

步驟一至四：讀取與簽署前檢查

1. Connect 並取得 account/chain；2. 驗證 token 與 destination，將輸入字串 parseUnits 成 bigint；3. 讀 balance/allowance 並 quote 指定 size；4. 建 minOut/deadline，再 simulate 完整呼叫。Quote 與 simulate 是 state snapshot，真正界限仍須在鏈上 enforce。

若 quotedOut = 2,000 USDC、slippage tolerance 50 bps，minOut = floor(2,000 × 9,950 / 10,000) = 1,990 USDC。這是額外允許的價格變化範圍，不是 fee 或保證成交價；不要把 slippage 設為 100% 解決 revert。

步驟五至八：授權、送出、確認

5. Allowance 不足時 approve 真正的 spender，等 receipt 後重讀 allowance；Permit/Permit2 則顯示 domain、spender、amount 與 expiry。6. 重新確認 chain/account，再由 wallet 簽署；7. hash 取得後持久化 pending operation，等 receipt；8. 看 status、正確 event 與 balance/position change，再等產品所需 finality。

Approval 成功後 swap 失敗，approval 仍在；兩筆 EOA transaction 不是原子流程。AA batch 是否全部回滾需讀 account 的 batch mode。Sponsored operation 則追 UserOp hash 與 UserOp receipt，不只追 bundle tx hash。

模擬、送出、持久化、等 receipt——並處理交易被加速或取消替換的情況

// ④ 模擬：失敗會在這裡丟錯，不花 gas（此例為 Uniswap V2 Router）
const { request } = await publicClient.simulateContract({
  account, address: ROUTER, abi: routerAbi,
  functionName: "swapExactTokensForETH",
  args: [amountIn, minOut, path, account.address, deadline],
});

// ⑥⑦ 送出後立刻持久化——使用者關掉頁面也找得回來
const hash = await walletClient.writeContract(request);
await savePendingOp({ opId, chainId, hash });

const receipt = await publicClient.waitForTransactionReceipt({
  hash,
  // 使用者在錢包裡加速或取消時，hash 會換掉——要跟著更新紀錄
  onReplaced: (r) => updatePendingOp(opId, { hash: r.transaction.hash, reason: r.reason }),
});

// ⑧ status 只描述這一筆；還要驗證 event 與實際的餘額變化
if (receipt.status !== "success") throw new Error("reverted: re-read state and re-quote");

失敗矩陣：不要因 timeout 就重送

狀態資產／結果復原
Wallet rejected未送出保留輸入，重新審閱
Simulation failed尚未鏈上執行修 allowance/balance/route，重取 quote
Submitted, receipt unknown可能仍 pending 或已執行追 hash/nonce/replacement，不盲目重送
Receipt reverted本交易 state rollback；gas 消耗讀 revert，取得新 state/quote
Source done, destination pending非原子跨鏈 claim追原 message ID，按協議 retry/claim

驗收與上線

測錯 chain、帳戶切換、不足 balance/allowance、quote 過期、minOut breach、wallet rejection、RPC timeout、nonce replacement、reorg 與 indexer lag。設定監控 inclusion latency、failure reason、successful cost、approval/role changes；保留 operation ID 與 chain/hash，避免只用使用者地址識別所有動作。

PM 定義完成條件、可恢復錯誤、support owner 與損失邊界。將 conversion、fees、price impact、slippage、MEV 與 network cost 分開顯示；比較 provider 時用同 chain、size、時間窗口與成功標準。

DeFi Integration: Intent, Execution, and Recovery

2026-10-08 · FOUNDATIONS · DEVELOPMENT · PRODUCT · RISK

In this note
  1. Pin the integration boundary
  2. Steps one to four: pre-signing checks
  3. Steps five to eight: authorize, submit, confirm
  4. Failure matrix: timeout is not permission to resend
  5. Acceptance and launch
  6. References

Use a USDC→ETH swap as the running example. Integration is more than writeContract: identify assets and units, explain authorization, constrain execution, establish completion, and recover from failures.

In three lines
  • A full integration is not one writeContract but eight steps: the first four only read and simulate at no cost; on-chain transactions and cost begin at step five.
  • A timeout is not a failure. The transaction may still be pending, or may already have executed; resending blindly can make the same thing happen twice.
  • "Done" is proven by the receipt, the right event and the actual balance change together, after the finality your product needs.

Where to start: front-end and back-end engineers → the eight-step diagram, the code and the failure state machine; PMs → the failure matrix and "Acceptance and launch", to define what counts as done and who owns cleanup.

Pin the integration boundary

Maintain a deployment manifest with chain ID, RPC, token addresses/decimals, Router/Factory/Permit2, ABI, code hashes, SDK/compiler versions, fork block, and official sources. Install selected versions with npm --save-exact, commit the lockfile, and use npm ci. latest, arbitrary explorer ABIs, and matching symbols are not reproducible identity.

Steps one to four: pre-signing checks

1. Connect and read account/chain. 2. Validate tokens/recipient and parse string amounts into bigint base units. 3. Read balances/allowance and quote the intended size. 4. Set minOut/deadline and simulate the complete call. Quotes and simulations are snapshots; constraints must remain enforced on-chain.

At a quoted 2,000 USDC and 50 bps tolerance, minOut is floor(2,000 × 9,950 / 10,000) = 1,990 USDC. Tolerance permits additional movement; it is not a fee or guaranteed price. Do not solve reverts with 100% tolerance.

Steps five to eight: authorize, submit, confirm

5. If allowance is insufficient, approve the actual spender, await its receipt, and reread allowance. For permit/Permit2, display domain, spender, amount, and expiry. 6. Recheck chain/account and ask the wallet to sign. 7. Persist the hash and pending operation, then await receipt. 8. Inspect status, expected events, and balance/position changes; wait for required finality.

An approval survives a later failed swap: two EOA transactions are not atomic. AA batch rollback depends on account execution mode. Sponsored actions need UserOp hash/receipt rather than only the bundle transaction hash.

Simulate, send, persist, await the receipt — and handle a sped-up or cancelled replacement

// ④ simulate: failures throw here at no gas cost (example uses the Uniswap V2 Router)
const { request } = await publicClient.simulateContract({
  account, address: ROUTER, abi: routerAbi,
  functionName: "swapExactTokensForETH",
  args: [amountIn, minOut, path, account.address, deadline],
});

// ⑥⑦ persist immediately after sending — recoverable even if the user closes the tab
const hash = await walletClient.writeContract(request);
await savePendingOp({ opId, chainId, hash });

const receipt = await publicClient.waitForTransactionReceipt({
  hash,
  // if the user speeds up or cancels in the wallet the hash changes — follow it
  onReplaced: (r) => updatePendingOp(opId, { hash: r.transaction.hash, reason: r.reason }),
});

// ⑧ status describes this transaction only; also verify the event and balance change
if (receipt.status !== "success") throw new Error("reverted: re-read state and re-quote");

Failure matrix: timeout is not permission to resend

StateAssets/resultRecovery
Wallet rejectedNot submittedPreserve inputs; review again
Simulation failedNo on-chain execution yetFix balance/allowance/route; requote
Submitted, receipt unknownMay be pending or executedTrack hash/nonce/replacement; do not blindly resend
Receipt revertedThis transaction rolls back state, consumes gasDecode failure; refresh state and quote
Source done, destination pendingAsynchronous claimTrack original message ID; protocol retry/claim

Acceptance and launch

Test wrong chain, account switching, insufficient funds/allowance, expired quote, minOut breach, wallet rejection, RPC timeout, nonce replacement, reorg, and indexer lag. Monitor inclusion latency, failure causes, successful-action cost, and permission changes. Persist operation IDs and chain/hash; an address alone cannot identify every action.

PMs define completion, recoverable errors, support ownership, and loss boundaries. Explain conversion, fees, price impact, slippage, MEV, and network cost separately. Compare providers with matching chains, sizes, windows, and success criteria.
